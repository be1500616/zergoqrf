**Task: Complete Transaction Management Feature Implementation**

**Objective**: Implement a comprehensive transaction management system for the ZERGO QR restaurant platform, covering payment processing, transaction tracking, refunds, and financial reporting as specified in `docs/stories/story-6.4-transaction-management.md`.

**Phase 1: Requirements Analysis and Architecture Planning**

1. **Story Analysis**: 
   - Thoroughly analyze `docs/stories/story-6.4-transaction-management.md` to extract all functional requirements, user personas, acceptance criteria, and technical specifications
   - Identify all transaction flows: payment processing, refund handling, transaction history, financial reporting, and audit trails
   - Map integration requirements with payment gateways (Stripe, PayPal, etc.) and accounting systems
   - Document security requirements for PCI compliance and financial data protection
   - Identify any gaps or ambiguities in requirements for clarification

2. **Architecture Design**:
   - Design the complete system architecture following vertical slice clean architecture patterns
   - Plan feature organization with proper layer separation (presentation → application → domain → infrastructure)
   - Design secure payment processing workflow with proper encryption and tokenization
   - Plan database schema for transactions, payment methods, refunds, and audit logs using Supabase
   - Design integration patterns for external payment processors and financial services
   - Plan real-time transaction status updates using Supabase realtime capabilities

**Phase 2: Backend Implementation (FastAPI)**

**Strict Adherence Required**: Follow all coding standards in `.augment/rules/fastapi-rules.md`

1. **Domain Layer** (`apps/backend/app/features/transaction_management/domain/`):
   - Create transaction entities and value objects (Transaction, PaymentMethod, RefundRequest, TransactionStatus)
   - Define repository interfaces for transaction operations and payment gateway integrations
   - Implement domain services for payment processing, refund logic, and transaction validation
   - Create domain events for transaction state changes and audit logging

2. **Application Layer** (`apps/backend/app/features/transaction_management/application/`):
   - Implement use cases: ProcessPayment, RefundTransaction, GetTransactionHistory, GenerateFinancialReport
   - Create DTOs for transaction data transfer and payment gateway communication
   - Design event handlers for transaction notifications and audit trail creation
   - Implement transaction reconciliation and settlement services

3. **Infrastructure Layer** (`apps/backend/app/features/transaction_management/infrastructure/`):
   - Implement repository patterns with Supabase integration for transaction storage
   - Create payment gateway adapters (Stripe, PayPal) following adapter pattern
   - Set up secure API clients for external financial services
   - Implement encryption services for sensitive financial data
   - Create audit logging and compliance reporting services

4. **Presentation Layer** (`apps/backend/app/features/transaction_management/presentation/`):
   - Design REST API endpoints for transaction operations with proper security
   - Implement webhook endpoints for payment gateway callbacks
   - Create secure admin endpoints for financial reporting and refund processing
   - Design Pydantic schemas with proper validation for financial data
   - Implement rate limiting and fraud detection middleware
