# Flutter SaaS Application Design & Development Standards

## 1. Design-First Development Philosophy

### Core Principles
- **Simplicity Over Complexity**: Every UI element must serve a clear purpose. Remove any component that doesn't directly contribute to user goals.
- **Predictable Interactions**: Users should never encounter unexpected behavior. All interactive elements (buttons, forms, navigation) must behave consistently across the entire application.
- **Immediate User Feedback**: Provide visual confirmation for every user action through state changes, animations, or loading indicators.
- **Performance as UX**: Target 60fps animations, <100ms response times for interactions, and <3s initial load times. Performance directly impacts user perception of quality.

## 2. Implement a Comprehensive Design System

### Theme Architecture (Required)
Create a centralized `ThemeData` configuration that controls all visual aspects:

**Color Scheme Implementation:**
```dart
// Use semantic color naming, never hardcoded colors
Theme.of(context).colorScheme.primary     // Brand primary color
Theme.of(context).colorScheme.secondary   // Accent/CTA color  
Theme.of(context).colorScheme.surface     // Cards, modals, sheets
Theme.of(context).colorScheme.background  // Screen backgrounds
Theme.of(context).colorScheme.onPrimary   // Text/icons on primary
```

**Typography Standards:**
- Define text styles for: Display, Headline, Title, Body, Label variants
- Use `google_fonts` package for professional typography
- Establish clear hierarchy with consistent sizing and weights

**Component Theming:**
- Pre-configure `ButtonTheme`, `InputDecorationTheme`, `CardTheme`
- Ensure all standard widgets inherit consistent styling
- Create custom component themes for app-specific widgets

## 3. Responsive Design Implementation

### Breakpoint Strategy
Define specific breakpoints and layouts:
- **Mobile**: <600px width - Single column, bottom navigation
- **Tablet**: 600-1200px width - Adaptive layouts, side navigation
- **Desktop**: >1200px width - Multi-column layouts, persistent navigation

### Responsive Widgets Usage
```dart
// Use LayoutBuilder for parent-constraint-based decisions
LayoutBuilder(builder: (context, constraints) {
  if (constraints.maxWidth > 1200) return DesktopLayout();
  if (constraints.maxWidth > 600) return TabletLayout();
  return MobileLayout();
})

// Use MediaQuery for screen-size-based decisions
MediaQuery.of(context).size.width > 600 ? WideLayout() : NarrowLayout()
```

### Adaptive Navigation Patterns
- **Mobile**: `BottomNavigationBar` or `Drawer`
- **Tablet/Desktop**: `NavigationRail` or persistent sidebar
- **Web**: Consider breadcrumbs and multi-level navigation

## 4. Professional Polish Implementation

### Animation Standards
**Implicit Animations (Preferred):**
- Use `AnimatedContainer`, `AnimatedOpacity`, `AnimatedPositioned`
- Duration: 200-300ms for micro-interactions, 300-500ms for transitions
- Curves: Use `Curves.easeInOut` for most animations

**Loading States:**
- Implement skeleton loaders using `shimmer` package
- Never show blank screens during data loading
- Provide progress indicators for operations >1 second

**Page Transitions:**
- Use `animations` package for professional transitions
- Implement `SharedAxisTransition` or `FadeThroughTransition`
- Maintain consistent transition timing across the app

### Micro-interaction Requirements
- **Button Press**: Subtle scale animation (0.95x) with 100ms duration
- **Form Validation**: Real-time feedback with color/icon changes
- **Success Actions**: Brief confirmation animations or haptic feedback
- **Hover States**: Color/elevation changes for web interactions

### Visual Asset Standards
**Icons:**
- Use single icon family (Material Icons, Cupertino, or custom set)
- Maintain consistent sizing: 16px, 24px, 32px, 48px
- Ensure proper contrast ratios (4.5:1 minimum)

**Images:**
- Use `cached_network_image` for network images
- Implement proper placeholder and error states
- Optimize images: WebP format, appropriate compression
- Use `flutter_svg` for scalable vector graphics

**Quality Assurance Checklist:**
- [ ] All colors reference theme, no hardcoded values
- [ ] Typography uses defined text styles
- [ ] Responsive behavior tested on 3+ screen sizes
- [ ] Loading states implemented for all async operations
- [ ] Animations feel smooth and purposeful
- [ ] Icons and images are crisp at all resolutions
- [ ] Performance metrics meet targets (60fps, <100ms interactions)
