Create a responsive layout system for the ZERGO QR Flutter app that implements standardized breakpoints and adaptive components following the existing Clean Architecture pattern in `apps/frontend/lib/features/`.

**Requirements:**

1. **Breakpoint System:**

   - Mobile: < 600px (single-column layouts)
   - Tablet: 600-1024px (two-column layouts)
   - Desktop: > 1024px (multi-column layouts)
   - Create a centralized breakpoint utility class in `lib/shared/responsive/`

2. **Adaptive Layout Widgets:**

   - `ResponsiveBuilder` widget that provides current breakpoint context
   - `AdaptiveLayout` widget that switches between layout configurations based on screen size
   - `ResponsiveGrid` widget for consistent spacing and component sizing
   - All widgets should integrate with the existing GetX state management

3. **Device-Specific Optimizations:**

   - Mobile: Touch targets minimum 44px, bottom navigation, swipe gestures
   - Tablet: Side navigation, optimized for landscape/portrait orientation changes
   - Desktop: Enhanced information density, hover states, keyboard navigation support

4. **Integration Points:**

   - Apply to existing diner PWA screens (`lib/features/diner/presentation/`)
   - Ensure compatibility with restaurant management screens
   - Follow existing Flutter coding standards from `rules/flutter-rules.md`
   - Use existing theme system and maintain consistency with current UI components

5. **Implementation Structure:**
   - Place responsive utilities in `lib/shared/responsive/`
   - Create example usage in diner menu screen to demonstrate mobile-first responsive behavior
   - Ensure PWA performance targets from Story 3.1 are maintained (< 2 second load on 3G)

**Deliverables:**

- Responsive utility classes and widgets
- Updated diner menu screen demonstrating responsive behavior
- Documentation of breakpoint system and usage patterns
- Integration with existing ZERGO design patterns and GetX architecture
